# 素材黑帧（录屏掉帧）

## 现象

录屏软件偶尔会掉一两帧，素材里就夹着一小段纯黑。
这段黑一旦落在镜头里，成片上就是**一闪而过的黑屏**——
观众会以为播放器坏了，而不是素材本来就这样。

本项目实测：159 分钟素材里只有 4 段黑帧，但其中一段落在镜头里，
成片上就闪了 0.40 秒的黑。

## 三个环节

### 1. 事前：扫素材

```bash
python scripts/scan_black.py --work-dir <work>
```

产出 `<work>/black_regions.json`：

```json
{
  "min_black": 0.1,
  "videos": {
    "v004_xxx": {"mtime": 1770000000.0, "regions": [[5.067, 6.567]]}
  }
}
```

- 阈值 0.1s（30fps 下 3 帧）：单帧偶发黑是编码噪声，不算问题。
- 结果按文件 mtime 缓存，**第二次跑几乎是瞬时的**，改素材才会重扫。
- 全部素材扫一遍约 6 分钟（159 分钟素材）。

### 2. 事中：编排时自动避开

`build_timeline.py` 会读 `black_regions.json`：
镜头取到黑帧就**截断窗口**，剩下的时长用定格补齐。

```
镜头本来要 v004@0 起 5.47s
→ v004 的 5.067-6.567 是黑
→ 截断成 v004@0~5.067（5.07s），后面 0.40s 定格补上
```

宁可画面停住最后一帧，也不闪黑。

日志会报告被截断的镜头：

```
WARN  s8_7: 素材 v004 在 5.1-6.6s 有黑帧（录屏掉帧），该镜已截断并定格 0.4s。
      画面停在最后一帧而不是闪黑，更好的做法是换一个锚点
```

**看到这条 warning 就要去换锚点**——定格只是兜底，
同一段内容在素材别处往往也有，换个锚点能既避开黑帧又让画面更好看。

### 3. 事后：质检兜底

`qc_video.py` 用 `blackdetect` 扫成片，阈值 **0.1s**。

> 早期版本阈值是 0.6s，结果**漏掉了一段 0.40 秒的黑闪**——
> 0.4 < 0.6，检测不到。掉帧造成的黑闪通常只有零点几秒，
> 阈值必须跟黑闪的长度同级，否则等于没有检查。

## 排查手法

### 怎么确认某段是真的黑

`-ss` 抽帧判断黑帧**不可靠**：录屏文件的时间戳可能有洞，
seek 会落到别处。用顺序解码看真实帧：

```python
import subprocess, numpy as np
# 顺序解码前 N 帧，逐帧算亮度
cmd = ['ffmpeg','-v','error','-i',src,'-frames:v','210','-vf','scale=160:90',
       '-pix_fmt','gray','-f','rawvideo','-']
raw = subprocess.run(cmd, capture_output=True).stdout
a = np.frombuffer(raw, dtype=np.uint8).reshape(-1, 90, 160).mean(axis=(1, 2))
dark = [i for i in range(len(a)) if a[i] < 2]
```

`blackdetect` 报的是**时间**，顺序解码看到的是**帧序号**，
两者对不上时（尤其是 VFR 录屏，帧率不是恒定 30）要靠
`ffprobe -show_frames` 的 `pts_time` 来对齐。

### 用 `-copyts` 检查 seek 准不准

`-ss` 放在 `-i` 前面会把时间戳归零，看不出真实位置：

```bash
ffmpeg -v info -copyts -ss 542.0 -i 素材.mp4 -frames:v 2 -vf showinfo -an -f null -
# 输出里的 pts_time 就是 seek 命中的真实时间
```

本项目实测 87 个镜头锚点：最大偏差 0.300s、中位 0.033s（一帧），
说明锚点是准的。

## 换锚点时怎么找

同一段内容往往在素材里出现多次（录屏的人会反复演示）。
换锚点时：

1. 在素材里找内容再次出现的时刻（`extract_frames.py` 的联系表能看）；
2. 确认那一段**没有黑帧**（查 `black_regions.json`）；
3. 确认那一段的内容和该句口播说的是同一件事；
4. 换完重跑阶段 7、8，并重跑质检。
