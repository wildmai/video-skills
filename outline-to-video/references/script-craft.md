# 干货/教学视频脚本方法论

写脚本时读这份。
目标不是"把大纲念完"，而是让人愿意看完并且记住。

## 一、成片骨架

```
钩子(0-8s) → 承诺(8-15s) → 分点(主体) → 收束(可执行清单) → CTA(可选)
```

**钩子**只做一件事：让人不走。
四种可用开法，按可靠性排序：

1. **痛点前置**——"每次都要手动点三下？这个视频给你一条命令解决。"
2. **结论前置**——"结论先说：只要改一个开关，速度能翻倍。"
3. **反常识**——"大多数人第一步就做反了，所以才慢。"
4. **结果前置**——直接甩出最终效果画面，再倒回去讲怎么做的。

**禁用开场**（这些会让观众在第 3 秒划走）：

- "大家好，欢迎收看我的频道。"
- 自我介绍、频道介绍、更新频率。
- "今天我们要讲的是……"（把目录念一遍）
- 寒暄与自我重复。

**承诺**用一句话说清"看完你能得到什么"，不要复述目录。

**分点**是主体。
每个点必须能独立成立，遵循"结论 → 论据 → 边界"三段式：

- 结论：先说这一点的答案。
- 论据：为什么成立，给一个具体场景或数据。
- 边界：什么情况下不适用（这是干货视频区别于水视频的关键）。

**收束**给可执行清单（3 条以内），不要总结全文。

**CTA**只在有明确动作时才加（关注/收藏/评论问题/看下一集），一句即可。

## 二、节奏参数

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 口播语速 | 约 5.2 字/秒 | 豆包 TTS 默认语速实测值（逐句合成，含每句首尾静音），一分钟约 310 字 |
| 单句长度 | 12-22 字 | 超过 22 字就拆句，TTS 换气会断在奇怪的位置 |
| 单段句数 | 2-3 句 | 一段对应一个信息单元 |
| 一个镜头 | ≥ 1.5s | 低于这个值会闪 |
| 画面切换间隔 | 8-12s | 一个知识点配一段画面，不是一个画面配十句话 |
| 信息密度 | 每 30s 一个新结论 | 没有新信息的段落直接删 |

**停顿**用短句制造，不要在 `vo` 里写"（停顿）"这类标记——TTS 会把它读出来。
想让某句之后留白，就把该句单独成段、后面跟一个短句收尾。

## 三、语言规则

**口语化**。
把书面语翻译成嘴说的话：

| 书面 | 口语 |
| --- | --- |
| 因此 / 从而 | 所以 |
| 进行配置 | 配一下 / 设置好 |
| 该功能具有… | 这个功能能… |
| 值得注意的是 | 注意，这里 |
| 综上所述 | 一句话收尾 |

**人称**用第二人称"你"，不用"我们"（"我们"会拉远距离）、不用"大家"。

**数字**用中文数字读起来更自然："三个步骤"而不是"3个步骤"；百分比和版本号保留阿拉伯数字。

**英文与缩写**要写成 TTS 能读顺的形式：
`API` → "A P I"，`Docker` → "Docker"（能被读），`JSON` → "J S O N"，或干脆换成中文说法。
不确定时在 `note` 里标注，必要时用 `additions.context_texts` 给发音提示。

**一句话内部不要出现「；！？」**。
这几个标点是 TTS 和字幕的断句点——写了以后「一句」会被拆成「两句」，
画面还是只有一个，就对不上了。（`validate_script.py` 会直接报 ERROR。）

**数字和量词**说完整：「五个部分」不要说「五块」，
「三步」不要说「三块」。分块、分组、分类的量词用「部分 / 组 / 类 / 项」，
「块」听起来像随手切的，不专业。

**不要在 `vo` 里写**：

- 画面描述（"这里我们看到屏幕上的按钮"）——画面归 `clips` 管。
- 括号提示、语气词标记、舞台指示。
- Markdown 记号（`**加粗**` 会被念成"星号"）。配音脚本会清理 Markdown，但清理会牺牲语义，所以源头就别写。

## 四、画面与口播的配合

**一条铁律**：每句口播都要有画面在讲同一件事。
画面在讲 A、口播在讲 B，是干货视频最劝退的失误。

**一句口播配一个画面。**
每节的 `vo` 行数必须等于 `clips` 个数，第 i 句配第 i 个画面。
镜头时长就是这句口播的时长，锚点指向该内容在素材里出现的时刻。

为什么这么严：时间线上画面和口播是各自独立排的，
只有数量一一对应、且都从同一句出发，两边才会严丝合缝。
数量对不上时只能按比例摊，各句长短不一（1.5s ~ 13s），
画面边界和句子边界会越走越偏——实测最大偏 6.3 秒，
观众听到「选好目录，一路下一步」时屏幕上已经在放下一段了。

具体要求：

- 录屏类素材取"有动作"的片段（正在点击、正在滚动），避开静态等待。
- 同一段素材不要连续出现在两节里；再次出现时至少隔一节。
- 一句口播讲不完一个画面时，**拆成两句**，配两个画面，不要一句配多段。
- 锚点要避开素材里的黑帧（录屏掉帧造成的纯黑），`validate_script.py` 会查。
- 需要强调某个结论时，在 `note` 里写"大字卡：xxx"或"放大此区域"，由后续渲染或剪辑环节落实。
- 素材本身信息密度低（大片留白、等待加载）时，宁可缩短口播也不要硬凑时长。

## 五、脚本字段怎么写

`vo` 只写"说出口的话"。
`clips[].note` 写"这个画面在干嘛 + 为什么选它"，方便用户确认和后期返工。
`role` 标出这一节在成片里的作用：`hook` / `point` / `example` / `payoff` / `cta` / `transition`。

## 六、反例对照

**差**：

> 大家好，今天我们来聊一聊关于 Docker 镜像优化的内容。
> 首先我们需要明确一个概念，那就是镜像和容器的区别。
> 在深入探讨之前，我想先介绍一下背景知识。

问题：开场自我寒暄；第二句是废话铺垫；第三句是元叙述。

**好**：

> 你的镜像拉一次要三分钟？三行配置，压到二十秒。
> 很多人镜像大，是因为每个文件都存了两份。
> 改一个文件，多层缓存就废一次。

问题：钩子给了具体数字和收益；每一句都是新信息；没有一句废话。

## 七、写完自检

跑一遍 `validate_script.py`，它会挡住这些：

- 口播句数和画面个数对不上 → 画面与口播会整体错位
- 一句里出现「；！？」→ 一句话被拆成两句，和画面对不上
- 锚点落在素材黑帧里 → 成片上闪黑
- 锚点往后素材不够铺满这句口播 → 只能定格，画面会停住

人肉再过一遍：

- 前 8 秒有没有给出"为什么值得看下去"？
- 每个分点是不是"结论 → 论据 → 边界"三件齐？
- 有没有哪句话删掉也不影响理解？有就删。
- 每一句口播，画面上是不是正在讲同一件事？
- 同一段素材是不是在相邻两节里出现？
- 结尾有没有一条能立刻照做的清单？
- 全文有没有出现"首先/其次/最后"式的流水账连接词？有就换成逻辑连接。
- 分块分类的量词对不对？（"五部分"不是"五块"）
