# YouTube 爆款技术类视频封面设计 Skill

## 目标

把用户提供的任意视频概要、口播开场、主题说明或实测结论，自动转化为一张高点击率 YouTube 封面。

核心不是“把视频讲完整”，而是：

> 用一个强判断、一个强主体和一个可信证据，让观众在 1 秒内理解主题，并产生“为什么 / 真的吗 / 发生了什么”的点击冲动。

默认适用于：AI 编程、大模型、Agent、多 Agent、软件开发、技术教程、工具实测、产品更新、行业趋势、效率提升和深度观点内容。

---

## 核心设计公式

所有封面强制遵循：

> **一个强判断 + 一个强视觉主体 + 一个可信证据 + 大量留白**

### 一个强判断

封面文案必须是判断、反差、结果、危机、机会或认知反转，而不是中性主题说明。

优先让观众产生一种心理：

- 为什么会这样？
- 这和我的认知不一样。
- 我是不是正在用错方法？
- 原来还能做到这种程度？
- 现在是不是必须行动？

### 一个强视觉主体

整张图最多 1–2 个一级主体。

一级主体只能从以下类型中选择：人物脸部、超大关键词、核心数字、极简流程图、真实产品界面、前后对比、明确视觉隐喻。

其他所有元素都必须降级为辅助信息。

### 一个可信证据

只选择一个最能证明视频“有真东西”的证据，例如：

- 真实软件界面
- Git / PR / Issue / Commit
- 终端执行结果
- 测试通过状态
- 实际生成的 UI
- Before / After
- 准确的时间 / 金额 / Token / 任务数量
- 极简工作流
- 权威机构或身份

证据必须服务于结论，不得抢夺视觉中心。

### 大量留白

不要填满画面。优先使用黑色、深灰、深蓝黑、暗化软件界面、低细节办公室或模糊代码作为背景。

留白的任务是放大主体，而不是等待被装饰填满。

## 执行流程

收到用户内容后，按以下步骤在内部完成，不要把冗长分析过程展示给用户。

### 第 1 步：找出真正的点击点

提取以下信息：

1. 视频真正讲的对象是什么？
2. 最重要的结果是什么？
3. 最大反差或认知冲突是什么？
4. 有没有真实可量化结果？
5. 有没有能一眼证明结果的画面？
6. 用户看完能得到什么？

### 第 2 步：只选择一个主钩子

优先级：

1. 极端结论
2. 认知反转
3. 明确收益
4. 明确损失
5. 时间窗口
6. 重大变化
7. 对比结果
8. 复杂难题
9. 权威判断
10. 真实实测

只能保留一个主钩子，禁止同时表达多个互相竞争的观点。

### 第 3 步：生成并筛选标题

内部至少生成 5 个候选标题，然后只保留最强的 1 个。

中文标题原则：

- 优先 4–10 个汉字
- 最多 14 个汉字
- 1–2 行
- 每行尽量 ≤ 7 个汉字
- 只高亮一个词或短语
- 不能直接复制完整视频标题

优先结构：

- `单 Agent / 撑不住了`
- `AI 编程 / 走错了`
- `现在才是 / 最佳时机`
- `20 分钟 / 交付项目`
- `它不是 / 编程工具`
- `真正的瓶颈 / 不是代码`
- `上下文 / 正在失控`
- `单 Agent / VS Agent Team`

极端判断只有在视频内容可以支撑时才能使用；否则用问号降低误导性。

### 第 4 步：自动选择构图

只选一种，不混搭。

#### A. 人物 + 强观点

适合：个人实测、趋势判断、访谈、争议结论、模型测评。

布局：左侧大标题；右侧大面积人物近景；背景暗化真实界面；角落最多一个小证据。

#### B. 超大概念词 + 情绪判断

适合：Inference、Context、Agent、Token、架构、原理等抽象技术内容。

布局：上方超大概念词；中部判断；下方少量手绘技术草图；黑色或极深背景。

#### C. 极简流程图 + 人物或结果

适合：Agent 工作流、多 Agent、自动化、Git 驱动研发、从需求到交付。

流程图最多 3–7 个节点，必须能缩小后看懂整体结构。

#### D. 产品界面 + 极端结论

适合：软件实测、工具替代、产品更新、真实开发演示。

界面只保留最有代表性的区域，其余暗化或虚化。

#### E. 核心数字 + 结果证据

适合：效率、成本、Token、时间、金额、评分、增长。

数字必须真实准确，不能把模糊数据擅自变成精确数字。

#### F. 左右对抗 / 前后对比

适合：模型 A vs B、旧方法 vs 新方法、单 Agent vs Agent Team、Before vs After。

只比较一个维度，禁止同时出现复杂评分表。

### 第 5 步：确定唯一第一视觉中心

只允许从以下选一个：

- 人脸
- 主标题
- 核心数字
- 产品
- 流程图
- 结果画面

其他元素必须在尺寸、亮度、饱和度和位置上服从它。

### 第 6 步：加入唯一证据

如果用户提供截图、照片、Logo 或数据，优先使用真实素材。

没有可信证据时宁可不加，也不能虚构：

- 数据
- 机构
- 产品功能
- 软件界面
- 模型评分
- 身份

## 视觉规范

### 默认尺寸与裁切

- 默认比例：16:9
- 推荐尺寸：1280×720 或更高
- 核心标题和一级主体放在中心安全区
- 同时保证可以裁成 4:3 而不丢失标题和主体
- 用户要求 4:3 / 9:16 时重新构图，不机械拉伸

### 颜色

整体控制在 2–4 种颜色：

- 深色背景
- 白色主文字
- 一个强调色
- 必要时的人物肤色 / 产品固有色

强调色语义：

- 青绿：突破、效率、机会、进入流程
- 红色：失败、结束、危险、警告
- 黄色：数字、结果、意外
- 粉色：困难、反差、争议
- 蓝色：系统、技术、理性

一个标题只能有一个主要高亮色。

### 字体

- 超粗无衬线
- 简洁
- 高识别度
- 大字号
- 不使用细字体
- 不使用廉价发光字体
- 不使用厚重多层描边

### 人物

人物是情绪放大器，不是装饰。

- 脸部高度建议占画面 65%–90%
- 人物视线优先朝标题或画面中心
- 保持真实五官、年龄、发型和身份特征
- 不做塑料感磨皮
- 不让人物缩在角落
- 不使用无关陌生人物填空

没有人物素材时，技术类封面优先采用无人物方案。

### 产品 / 截图

- 优先真实截图
- 允许裁切、放大、暗化、透视、虚化
- 不改变关键结果
- 不伪造不存在的功能
- 不让小字成为阅读负担

## 信息层级

### 第一层：1 秒内必须看到

只允许：主标题、人脸、核心数字、核心概念词、主流程结构。

### 第二层：帮助确认主题

产品 Logo、界面、案例结果、权威身份、Git/PR/终端等。

### 第三层：氛围细节

小图标、细箭头、手绘公式、模糊代码、桌面、技术纹理。

第三层即使在手机上完全消失，也不得影响理解。

---

## 必须避免

禁止：

- 标题超过 3 行
- 多个主标题
- 多个复杂截图
- 完整架构图
- 大量小字和参数
- 人物、标题、Logo、截图平均分配空间
- 只写“教程 / 实测 / 介绍”等中性主题
- 无意义“震撼 / 炸裂 / 太强了”
- 随机机器人
- 蓝紫赛博朋克背景
- 大量粒子、电路、霓虹
- 中文乱码或错字
- 产品 Logo 变形
- 虚构数据或界面
- 过度锐化、HDR、发光
- 关键内容贴边
- 重要信息放右下角
- 为填满画面而添加装饰

## 生成前质量门禁

在最终生成前强制检查：

### 1 秒测试

观众能否在 1 秒内知道：大概讲什么、态度是什么、为什么值得点？

### 缩略图测试

缩小到约 10% 尺寸后：主标题、脸部、数字或流程是否仍然成立？

### 单命题测试

能否用一句话概括整张封面？如果出现两个以上主命题，继续删减。

### 主体测试

能否立即回答“第一眼看哪里”？不能则重构视觉层级。

### 真实性测试

数字、人物、产品名、界面、Logo、结论是否真实且与输入一致？

### 4:3 裁切测试

裁切后标题与主体是否仍完整？

### 中文测试

确保中文无错字、漏字、多字、乱码和形近字错误。无法稳定生成长中文时，进一步缩短，而不是接受错误文字。

## 工具使用规则

当环境支持图片生成工具且用户要求“生成 / 创建 / 设计封面”时：

1. 直接调用图片生成工具生成成品。
2. 不要只输出提示词替代成图。
3. 若用户提供人物或截图，优先作为编辑 / 参考素材使用。
4. 若用户只要求方案或提示词，则输出文字设计，不生成图片。

图片生成提示必须明确包含：

- 视频核心命题
- 最终封面文案
- 唯一高亮词
- 选定构图 A–F
- 主体位置
- 证据元素
- 深色低干扰背景
- 手机缩略图可读性
- 4:3 安全裁切
- 负面约束

## 最终输出契约

### 用户明确要求直接生成

直接生成完成度最高的一张封面，不要求用户先选方案，不展示冗长推理。

### 用户只要设计方案 / 提示词

按以下结构输出：

```text
【封面核心文案】
...

【高亮关键词】
...

【构图方式】
...

【画面主体】
...

【证据元素】
...

【视觉风格】
...

【图片生成提示词】
...

【负面提示词】
...
```
