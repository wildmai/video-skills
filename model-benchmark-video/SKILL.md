# 模型测评/对比视频创作 SOP

## 目的

把"模型 benchmark 实测"做成可复制的视频创作流水线。核心交付是**能力分层框架 + 对决题库**——这是模型测评视频的灵魂；口播稿、分镜、标题封面等通用环节衔接 viral-video-creator 完成，本 skill 不重复定义。

**同样采用阶段门禁**：能力框架确认后才设计题库，题库确认后才进入通用视频创作阶段。

## 触发场景

- 用户要做某模型的实测/上手/测评视频（单模型）
- 用户要做模型对比视频：新旧版本对比、同厂双型号（如 Pro vs Flash）、多模型横评
- 用户提供模型卡/榜单链接（ModelScope、HuggingFace、Artificial Analysis、LMArena 等）要求据此设计测评

## 三种测评模式

| 模式 | 适用 | 叙事结构 |
|---|---|---|
| 单模型独立测评 | 新模型发布抢鲜 | 能力金字塔逐层爬，看模型"爬到第几层开始吃力" |
| 双模型同题对决 | 同厂双型号 / 新旧版本 | 同题双屏 + 比分板，差距曲线设计成波浪形（平→开→贴→鸿沟），忌单调递增 |
| 多模型横评 | 3 家以上旗舰对决 | 每层一个擂主，金字塔变"天梯榜"，收尾给总榜 |

## 执行流程

### 阶段 0：模型调研（数据可信度是生命线）

1. 拿到目标模型的官方模型卡（ModelScope / HuggingFace / 官网 API 文档）。
2. **动态渲染页抓不到正文时**（ModelScope、artificialanalysis.ai 都是 JS 渲染）：改用 WebSearch 多源交叉验证，或请用户直接粘贴正文。官方模型卡 > 媒体二手数据，冲突时以官方为准并在文档标注口径。
3. 必采数据清单：参数量（总/激活）、上下文窗口、思考模式档位、价格、各能力维度 benchmark 分数、对标模型分数。
4. 产出 `00-模型数据卡.md`：全部数字入表，标注来源（官方/媒体）。

### 阶段 1：能力分层框架（核心，必读 references/capability-framework.md）

按能力金字塔分层设计测试关卡，铁律：

- **每关只考一项能力**，按认知层级严格递进：语言 → 知识 → 推理 → 代码工程 → 长上下文 → 智能体（顶层是下层的综合）
- 每关配**一个专属数字锚点**（对应官方 benchmark 分数）
- 可利用维度不止任务难度：思考模式档位（Non-think/High/Max）、上下文长度、并发/延迟都可作升档轴
- 找"反常识点"当钩子：同一模型不同模式分数差数倍、小模型某层反超大模型、思考补不齐知识储备等
- 先抑后扬埋点：让强模型/贵模型在前几关"不值这个价"，后面收账
- 名场面放在差距最大的一层，留足 10 秒特写

产出 `01-能力框架.md`：层级表（层级 | 能力 | 测试设计 | 模式档位 | 各模型锚点分数 | 预期结论），与用户确认后才进阶段 2。

### 阶段 2：对决题库设计（必读 references/test-design.md）

- 每关 1 道主测试题 + 2 道备选题；全部**提前离线跑过、答案验证过、双模型表现差异已确认可复现**
- 优先选"可自动判分"的题型（测试红绿、找针命中率、终端任务成败），结果客观可定格
- 产出 `02-题库.md`：题目原文 | 考察能力 | 标准答案/判分标准 | 预跑结果 | 备选方案

### 阶段 3 起：衔接 viral-video-creator

框架和题库确认后，调用 viral-video-creator skill 的阶段 2–4（口播稿 → 分镜 → 标题封面），把能力框架作为其"阶段 1 大纲"的已定稿输入。通用规范（七段式、钩子密度、禁忌清单）以 viral-video-creator 的 references/production-spec.md 为准。

### 产物目录

沿用视频项目目录约定：`video-projects/<项目名>-<日期>/`，先建 `00-进度.md` 记录各阶段状态，支持跨会话续作。本 skill 新增产物：`00-模型数据卡.md`、`01-能力框架.md`、`02-题库.md`。

## 硬性规则

- 数据不编造：所有 benchmark 数字必须来自阶段 0 的采集记录，标【假设】或【媒体口径】
- 题库不裸奔：没预跑验证过的题不进正式录屏
- 分层不混搭：一关只考一项能力，数字锚点一关一个
- 门禁不跳过：框架、题库各过一次用户确认
