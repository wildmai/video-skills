# 对决题库设计规范

> 题库是测评视频的可信度根基。一条铁律：**没预跑过的题，不进正式录屏。**

## 〇、观众视角三标准（最高优先级，2026-08 实战教训）

用户连续三轮推翻题库（能力维度→全自足→日常向）后沉淀的出稿标准：

1. **日常可感**：优先选观众日常生活/工作里的真实场景（写周报、凑单满减、避坑问答、小游戏、账单可视化），少用奥赛题、终端排障这类"离观众远"的题目——除非名场面必须
2. **全自足**：题目原文、prompt、标准答案、素材文件全部写死在文档里，用户拿到手复制即测，不存在"请自备 XX"的缺口（版权素材一律换公版/自制素材）
3. **有镜头点**：每关设计时就想好成片画面——弹幕盲评、答错打脸、红绿对比、大屏高亮；产物最好是"实体"（网页、游戏、报告），能当场打开展示

## 一、选题三原则

1. **可复现**：题目、环境、判分标准全部文档化，任何人照做能得到同样结果
2. **可判分**：优先客观判分——测试红/绿、找针命中、答案唯一；主观题（文案质量）用盲评并明示标准
3. **差异可预期**：预跑确认模型间表现差异真实存在且方向稳定，再定稿。差异不如预期时换题或改话术，不硬录

## 二、各层题型建议

| 层级 | 主题型 | 判分方式 | 备选题 |
|---|---|---|---|
| L1 语言 | 同一段文案改写 + 盲评 | 盲评打分（标准事先写死） | 长文摘要字数/要点覆盖 |
| L2 知识 | 冷门事实问答（答案唯一） | 对/错 | 中文专业领域问答 |
| L3 推理 | 奥赛级数学题（有标准答案） | 答案对/错 + 证明完整性 | 多步逻辑谜题 |
| L4 代码 | 从 0 生成可运行小工具 | 跑通/跑不通 + 功能点清单 | 真实开源项目注入 bug 修复 |
| L5 长上下文 | 百万字文档找针 | 命中/未命中 | 跨章节多跳推理问答 |
| L6 智能体 | 可自动判分的终端排障 | 服务恢复/超时 | 多工具编排任务（查数→对比→成稿） |

## 三、每道题的文档模板

```
## 题目：<名称>
- 考察层级：Lx <能力名>
- 题目原文：<完整 prompt，含系统提示词>
- 模式档位：Non-think / Think High / Think Max
- 标准答案 / 判分标准：<写死，不接受"看着像对">
- 预跑结果：模型A → <结果+耗时>；模型B → <结果+耗时>
- 差异稳定性：连续 3 次结果是否一致
- 画面要点：<录屏时哪个瞬间值得定格>
- 备选：<换题方案 / 话术调整方案>
```

## 四、预跑检查单

- [ ] 每关 1 道主题 + 2 道备选题全部预跑完毕
- [ ] 答案已离线验证（奥赛题对官方解答、事实题查权威来源）
- [ ] 双模型差异方向与大纲预期一致；不一致已改题或改话术
- [ ] 思考模式特殊触发方式（如特殊系统提示）已按官方文档跑通
- [ ] L6 终端任务环境可一键重置（录屏 NG 重来用）
- [ ] 录屏用账号的额度/并发足够跑完全部题（注意峰谷计费时段）

## 五、诚信红线

- 不挑选只对自己结论有利的运行结果；翻车如实呈现，转为"先抑后扬"素材
- benchmark 分数引用必须标注口径（官方自测 / 第三方复测 / 媒体口径）
- 对比测试保持条件一致：同 prompt、同模式档位、同温度参数，差异条件必须口播声明
